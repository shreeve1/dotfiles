# Project Memory

What a future session in this project would otherwise have to re-learn: decisions, gotchas, how the stack is set up, how the owner wants work done here. Operated by the `personal-memory` skill; the project's `AGENTS.md` names where it is installed.

Git is optional. In a git repo, memory `.md` files are tracked and `raw/` is git-ignored; never store credentials, since history keeps them. Outside a repo, memory works the same with no history. There are no hooks: run `gate.py audit` yourself.

## Purpose

- Decisions a future session would otherwise re-litigate.
- Gotchas, tool quirks and non-obvious facts about this project's stack.
- How a recurring task in this project goes.
- The owner's preferences and corrections for working here.
- Lasting facts about the things this project keeps coming back to (Client Memory, when set up).

Not memory: what the project's own docs or code already state (link to them), one-off task details, work still in motion, and runbooks a person follows (those go in the project's `docs/`).

## Safety

- Do not store secrets, tokens, passwords, API keys, bearer strings, OAuth credentials, or credential-like config. Omit them automatically; never ask.
- Prefer summaries over raw content. Store raw snippets in `raw/` only when explicitly asked, with credentials stripped.

## Directory Layout

```text
memory/
├── README.md
├── TEMPLATES.md
├── schema.json    # topics and Client Memory settings
├── index.md
├── glossary.md    # shorthand -> identity
├── rules.md       # routing table: task trigger -> skills and memory files
├── preferences/
├── docs/
├── workflows/<topic>/   # index.md generated by indexes.py
├── decisions/<topic>/   # index.md generated by indexes.py
├── <client_folder>/     # Client Memory, only when schema.json sets it up
│   └── _hubs/           # generated by hubs.py
└── raw/                 # git-ignored
```

Create folders only as content needs them.

## Capture

No candidates and no approval step, except for procedures (`type: procedure`): one is saved only after the owner says yes to the full file. At the end of each task, when a capture trigger fired (a correction, a stated rule or preference, a described workflow, a settled decision, or a reusable fact discovered while working), the agent writes it to the right file, updates `index.md`, runs `indexes.py` for workflow/decision changes (and `hubs.py` for Client Memory) and `gate.py audit`, commits if the project is a git repo, and reports what it saved. Without Python, use the `personal-memory` skill's manual checks instead.

## Client Memory

For things the project keeps coming back to (hosts, services, customers). Notes live at `memory/<client_folder>/<subject>/<short>/<slug>.md`, one fact per note; `client_folder` and `client_subjects` are set in `schema.json`. `<short>` is the short name from `glossary.md`. Run `hubs.py` after writing; edit hubs by hand only without Python, following the skill's manual hub instructions, and give each an `index.md` row under `## Client Hubs`. Unused when `client_subjects` is empty.

## Naming

Lowercase hyphenated slugs. `docs/<slug>.md` one subject per file; `workflows/<topic>/<slug>.md`; `decisions/<topic>/decision-<slug>.md`. Topics come from `schema.json` (a new topic only with the owner's OK). 15-file rule: a folder with more than 15 `.md` files directly gets topic subfolders; `gate.py crowded` reports it.

`glossary.md` answers "who/what is this?"; `CONTEXT.md` at the project root answers "which meaning?" for contested terms.

## Cross-linking

Link with project-relative paths starting with `memory/`. Link outward only, to the 1-3 notes a note depends on or informs. Backlinks are computed: `gate.py backlinks memory/<path>.md`.

## Tolerant Reads

Never refuse a memory file for missing optional frontmatter, an unknown `type`, a missing `index.md`, or a broken link.

## Maintenance

- Files state only what is true now. Overwrite in place; at most one `Changed YYYY-MM-DD: <why>` line when the reason still matters. A note that is no longer true is deleted.
- At most 6144 bytes per note, `summary` at most 160 characters. `gate.py audit` warns.
- A note older than 90 days (`gate.py stale`) is re-grounded before it is relied on.
