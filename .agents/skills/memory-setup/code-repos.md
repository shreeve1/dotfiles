# Code repos and wiki sources

Read before sorting whenever the target is code or the source is a wiki. Removal waits until the owner approves and every reader is accounted for.

- **Find readers before removal.** Check code imports and tools, container mounts, continuous integration, scripts, `.gitignore`, and agent or assistant configs inside and outside the repo. Ask about external configs the session cannot inspect; the owner's answer that nothing outside the repo reads the source completes that check, while no answer leaves removal waiting. Each reader is repointed, removed with the source, or blocks removal; tell the owner which. A wiki used by a live service cannot disappear just because its notes were sorted.
- **Protect foreign changes.** List changes not made by this session first. Archive uncommitted edits to the source in a tarball outside the repo, verify its contents, then sort those edits too and remove the source once approved, rather than treating those edits as a blocker. In a folder without git, treat all source content as uncommitted. If tar is absent, use an available archive tool or a verified copy outside the folder; if neither is possible, leave the source in place. Never stash, reset, restore, checkout or clean. Stage only your own exact paths; for approved source removal include the deletion after archiving, while in retained files with foreign edits stage only your own changes or leave them uncommitted and report the blocker.
- **Fix live references, keep history.** Repoint instructions, docs, skills and configs to the memory note or the real doc. For history-only pages, use a permalink at the last commit that contained the page when there is a web remote; otherwise remove the live pointer. Historical mentions in old plans, changelogs and architecture decision records stay. Search again after removal to catch unresolved live references.
- **Replace old maintenance instructions.** Instructions that said "update the wiki" now say "run the memory check" and point to `personal-memory`. Preserve unrelated instructions.
- **Test after removing serving code.** Run the project's test suite after removing code that served the old source, and whenever code changed. Report failures and unavailable checks explicitly; do not claim a clean migration without evidence.
