First Principles

strip to axioms, rebuild

What is tralph, minimally? A board, a scheduler, workers, a merge. Each reduced to its irreducible form.

ax.0The board IS the graph

No new graph format. The frontier is a query over blocked_by frontmatter — gralph already does exactly this for GitHub issues.

ax.1Scheduler = pure function

A tiny ready(issues) → set. Everything else is adapters around it.

ax.2One worktree per ticket

Lane branch auto/<id>, created lazily at claim time.

ax.3Merge in topo order

Blockers land before dependents. Two chain strategies: branch dependents FROM the blocker's lane tip (max parallelism, fragile) — or the simpler pick: dependents branch from integration only after blockers landed. Serializes chains, parallelizes independent subtrees.

ax.4Merge is a ticket too

A synthetic integrate node that every leaf blocks — the same loop executes the merge step.

ax.5Predict conflicts at graph time

Intersect declared file scopes; overlapping tickets get a synthetic dependency edge (serialize instead of parallel). No declared scopes? A cheap parallel scout pass predicts touched files first.

ax.6Crash-only state

All state lives in ticket frontmatter (status, lane, owner, heartbeat) + git worktree list. A restarted driver reconstructs everything.

ax.7Dumb driver, smart workers

Driver stays bash; intelligence stays in worker skills — the Ralph philosophy. (Inversion considered: AgentTeams captain as scheduler, members prompted work only in <worktree>.)

ax.8Verify twice

In-lane before merge, and re-verify the integration branch after each landing — catches semantic conflicts git merges cleanly. Both-green-merged-red auto-opens a repair ticket into the same graph.

ax.9Kill shared-file conflicts by design

progress.md would conflict across lanes → per-lane progress.d/<id>.md, concatenated on landing. Board writes happen ONLY by the driver on main; workers never touch .kanban in their lane.

SCAMPER

mutate the existing machine

Take today's tralph and turn each SCAMPER dial.

S
Substitute

tmux monitoring → systemd-run transient units per lane (already used for memory caps): free restarts, journal, OOM handling.

Polling adapter → headless one-shot sessions (omp -p style) for parallel mode; tmux stays only for attended single-lane debugging.

C
Combine

Port gralph's wave/frontier engine to read .kanban instead of GitHub — 90% of the parallel logic is already written and tested.

A
Adapt

Take dsh-board's lane mechanics wholesale: laneBranches, ff-only landing, bounce-with-reason.

Adaptive jobs cap: free RAM ÷ 8G worker cap, plus per-provider rate-limit stagger.

M
Modify / Magnify

Extend the sentinel protocol with RALPH_RESULT MERGED/CONFLICT variants.

P
Put to other use

The merge step IS the review: an integrator session reviews the integrated diff as it lands each lane.

E
Eliminate

Review tier by diff: docs-only tickets skip the fresh-session review entirely.

R
Reverse

Big-bang merge at the end → a continuous merge queue: land + rebase one lane at a time, so conflicts surface early and small.

Analogy: CI merge queues

GitHub merge queue · bors

What do battle-tested landing systems already know that tralph doesn't? Board the train — locomotive first.

LOCO · THE LANDING PROTOCOL

bors-style: a lane must be rebased on the latest integration tip AND green before landing. The driver auto-rebases and re-runs verification. Steal this wholesale.

⊃⊂
CAR 1 · BATCCH LANDING

Docs-only / disjoint lanes land as one octopus batch, verified once — bisect the batch on red (bors batching).

⊃⊂
CAR 2 · PRIORITY LANES

A P0 ticket preempts the merge queue.

⊃⊂
CAR 3 · TRAINS

Group tiny tickets into one lane to amortize session + worktree overhead — ticket cost is not uniform.

Constraint: what if merge conflicts were IMPOSSIBLE?

design under an absolute
DISJOINT WRITES ENFORCED

Forbid the failure instead of handling it. Partition the repo at decompose time; every wall below is load-bearing.

ZONE A · OWNERSHIP AT DECOMPOSE TIME

/to-tickets declares a files: scope per ticket. Overlapping scopes = automatic dependency edge. The scheduler enforces disjoint writes in flight — conflicts become impossible by construction; merge is always ff/trivial.

ZONE B · SCOPE IS ENFORCEABLE

The driver diffs the lane against its declared scope; an out-of-scope diff = bounce. Same trick as dsh-board's outOfScope.

ZONE C · UPGRADE THE FORMAT

This pushes intelligence into /to-tickets: add a "parallel-safe" pass that emits scopes + extra edges. Upgrade the ticket format, not just the loop.

Biomimicry + Wild

borrow from biology, then get weird

Green spores are borrowed from living systems; purple ones escaped containment.

🐜 ant colony Workers leave pheromone — progress.d notes. Later workers on sibling tickets read only notes from LANDED lanes, avoiding half-truth context from unlanded work.
🛡 immune system A roaming low-cost checker session re-runs random landed verifications overnight — catches bit-rot introduced by later landings.
🍄 mycelium Share one git objects store across worktrees (worktrees already do) + shared pnpm store + shared build cache per run — N lanes at ~1.2× the cost of one.
⚡ wild · speculation Speculative execution: start a dependent ticket in a lane branched from its blocker's unreviewed tip; if the blocker bounces, discard the speculation. Tokens are cheap at MiniMax prices — wall-clock is not.
⚡ wild · the race Two workers race the same hard ticket with different models; first green diff wins, loser discarded.
⚡ wild · burn-down TV The graph as live mermaid in run-report.md, regenerated each wave — a watchable board burn-down.
⚡ wild · bounce mining The shepherd greps historic bounce reasons to auto-tune the jobs cap and scope declarations.
